Context-Driven Development Framework

Context replaces prompting.

Core principle. The problem is never the model — it is the absence of structured context. You stop iterating on output and start iterating on the system that produces output. Without context the system guesses; with context, it executes with intent.

The Workflow

Ground truth

/context/ + /input/

Business reality (read-only) plus external materials a subject brings in.

→
System

/specs/ — the decisions

Per-subject working docs that translate ground truth into decisions an agent can act on.

→
Deliverable

/output/

Generated artifacts. Never hand-edited — sources are regenerated.

Iteration loop If the output is wrong, fix the system, not the output. Update /specs/ (subject decision) or /context/ (general truth), then regenerate. When a learning generalizes beyond one subject, log it in /iterations/ so the system gets smarter over time.

The Five Layers

/context/Read-only
Ground truth

Structural reality of the business: voice, audience, services, pricing, constraints. Organized by topic, shared across every subject.

/specs/Editable
Per-subject decisions

One folder per subject (client, project, campaign). Scope, decisions, internal notes. Where the system actually makes choices.

/input/Read-only
External material

Briefs, PDFs, photos, transcripts the subject brings in. Same slug as /specs/ and /output/. Never mixed with /context/.

/output/Generated
Artifacts

Source files (HTML, MD) and rendered deliverables (PDFs). Reproducible from /context/ + /specs/ + /input/. Never edited by hand.

/iterations/Append-only
System memory

Each meaningful learning logged as v{N}-{slug}: manifest, feedback, changes, principle. The memory that prevents repeating mistakes.

A Session, Start to Finish

1

Read context

Agent reads /context/ first. This is ground truth — do not contradict it.

2

Open the subject

cp -r specs/_template specs/{slug}/. Same slug in /input/ and /output/.

3

Load inputs

Drop client materials into /input/{slug}/. Reference them from /specs/.

4

Generate

Produce sources and rendered files into /output/{slug}/. Don't edit by hand.

5

Fix the system

On wrong output, update /specs/ or /context/. Regenerate, don't patch.

6

Log learnings

If the lesson generalizes, append /iterations/v{N}-{slug}/ and update /context/.

The Three Rules

Rule 1 · The iteration rule

Do not fix the output. Fix the system. The wrong file is a symptom — the cause lives in /context/ or /specs/.

Rule 2 · Separation of concerns

General truths → /context/. Subject-specific facts → /specs/{slug}/. External material → /input/{slug}/. Never mix.

Rule 3 · Generalize forward

When a per-subject lesson applies elsewhere, lift it to /context/ and log /iterations/. The system compounds.
